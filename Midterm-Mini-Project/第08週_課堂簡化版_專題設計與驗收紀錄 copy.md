### 6. 開發過程遇到的問題與解決方式

**問題一：Pydantic 模組無法正常載入**

本機 Windows 安全政策阻擋 pydantic_core 模組載入，導致相關套件無法正常使用。

解決方式：改用 JSON Schema 進行結構化輸出，並使用 Python 內建 urllib.request 發送 API 請求，避免依賴受限制的模組。

**問題二：API 金鑰讀取失敗**

初次執行時，程式無法正確讀取 OPENAI_API_KEY。

解決方式：檢查 .streamlit/secrets.toml 的檔案位置及設定格式，修正後成功執行 API 測試。

**問題三：公告資訊不足**

部分公告沒有提供明確截止日期或作業題數，若 AI 自行補全，可能造成錯誤資訊。

解決方式：在程式規則中要求 AI 不得編造資料，缺少的日期以「未知」表示，其他缺少的資訊放入 missing_info 欄位。

### 7. 專題反思

本次專題讓我了解，生成式 AI 不只是產生文字，也可以透過 JSON Schema 將非結構化的公告轉換成固定欄位的資料。

我認為最有幫助的欄位是 deadline、todo_items 和 missing_info。deadline 能協助學生確認繳交期限，todo_items 能將老師的要求拆解成待辦事項，missing_info 則能提醒學生哪些資訊還需要進一步詢問老師。

在開發過程中，最大的困難是本機套件受到 Windows 安全政策限制，導致原本預期的程式實作方式無法順利執行。後來改用 JSON Schema 搭配 urllib.request，成功完成本機 API 呼叫及結構化輸出測試。

我也學到，不能只因為 AI 成功產生 JSON 就認為結果正確，仍需要人工對照原始公告，確認日期、作業內容及缺少資訊是否正確。
